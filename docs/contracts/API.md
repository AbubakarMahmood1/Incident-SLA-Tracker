# HTTP API Contract

## General rules

- Base prefix: `/api/v1`
- Media type for JSON commands: `application/json`
- Authentication: `Authorization: Bearer <JWT>`
- Every incident mutation requires `Idempotency-Key`.
- Command JSON rejects unknown fields.
- UUID path and body identifiers use canonical UUID syntax.
- Error bodies generated by the service layer use:

```json
{
  "error": {
    "code": "stable_machine_code",
    "message": "bounded human-readable explanation"
  }
}
```

FastAPI request-validation errors retain the framework's standard `422` shape.

## Authentication

### `POST /api/v1/auth/token`

OAuth2 password-form fields:

- `username`: normalized owner-provisioned username
- `password`: plaintext credential transported only over deployment-provided TLS

Success:

```json
{
  "access_token": "<signed JWT>",
  "token_type": "bearer"
}
```

Unknown user, inactive user, and wrong password all return the same `401 invalid_credentials` response. Version 1 has no refresh, revocation-list, password-reset, or public-registration API.

## Idempotency header

Accepted syntax:

```text
^[A-Za-z0-9][A-Za-z0-9._:-]{7,127}$
```

The receipt key is `(actor_id, idempotency_key)`. A completed replay with identical command type and canonical payload returns the original incident. A materially different reuse returns `409 idempotency_conflict`.

The header does not deduplicate GET requests, commands by another actor, or external notification delivery.

## Incident representation

An incident response includes:

- current aggregate fields and lifecycle timestamps;
- reporter and optional assignee summaries containing only identifier, username, and display name;
- immutable SLA target seconds, start, and deadlines;
- independent response and resolution outcomes; and
- independent breach evidence.

Possible objective outcomes are `pending`, `met`, and `breached`. Once a breach is persisted, a later acknowledgement or resolution does not convert it to met.

## Commands

### `POST /api/v1/incidents`

Request:

```json
{
  "title": "Payments returning 503",
  "description": "Checkout cannot authorize new payments",
  "priority": "critical"
}
```

- Actor becomes reporter.
- Priority is one of `critical`, `high`, `medium`, `low`.
- The policy snapshot and `incident.created` event commit with the incident.
- Success: `201`.

### `POST /api/v1/incidents/{incident_id}/assign`

```json
{
  "assignee_id": "c5f14936-0ee4-4eb7-a123-5e79d25d7773"
}
```

- Administrator only.
- Incident must be `open` or `acknowledged`.
- Assignee must exist and be active.
- Assigning the current assignee is a conflict rather than a silent no-op.
- If an objective is already overdue but has not yet been recorded, assignment records the breach and directs the transactional outbox to the newly assigned active user.

### `POST /api/v1/incidents/{incident_id}/acknowledge`

- Current assignee or administrator.
- Only valid from `open`.
- Due breach evidence is persisted before acknowledgement in the same transaction.

### `POST /api/v1/incidents/{incident_id}/resolve`

- Current assignee or administrator.
- Valid from `open` or `acknowledged`.
- From `open`, emits an implicit acknowledgement event immediately before resolution.
- Due response and resolution breaches are persisted first.

### `POST /api/v1/incidents/{incident_id}/close`

- Reporter or administrator.
- Only valid from `resolved`.

Version 1 intentionally has no generic update, status-patch, reopen, delete, or priority-change endpoint.

## Queries

### `GET /api/v1/incidents`

Parameters:

- `offset`: integer, minimum 0
- `limit`: integer, 1 to 200, default 50
- `status`: optional lifecycle value
- `priority`: optional priority value
- `search`: optional text, at most 255 characters

Non-administrators receive only incidents they reported or are assigned. Search escapes PostgreSQL wildcard characters and treats the supplied text literally. Ordering is newest creation first, with UUID as a stable tie-breaker.

### `GET /api/v1/incidents/{incident_id}`

Returns one visible incident or an authorization/not-found error.

### `GET /api/v1/incidents/{incident_id}/events`

Returns event rows in ascending global sequence order. The event `effective_at` may precede `occurred_at` for delayed breach detection.

## Health

- `GET /health/live`: process liveness; does not prove dependencies.
- `GET /health/ready`: `200` only after a PostgreSQL `SELECT 1`; otherwise `503`.

## Status-code summary

| Status | Meaning |
|---|---|
| `200` | Successful query or mutation |
| `201` | Incident created |
| `401` | Missing, malformed, expired, or untrusted credentials |
| `403` | Authenticated actor lacks permission |
| `404` | Required aggregate or active assignee not found |
| `409` | Invalid transition, duplicate assignment, incomplete prior receipt, or idempotency conflict |
| `422` | Request shape, bound, UUID, enum, text, or idempotency-key validation failed |
| `503` | Readiness dependency unavailable |
